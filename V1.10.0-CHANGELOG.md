# บ้านผีสิง v1.10.0 — บัญชีผู้เล่นและล็อบบี้

- Google OAuth only; no game password, real name, gender, or phone number.
- First sign-in asks for a 2–18 character in-game name and an avatar from the existing character art.
- Main lobby uses the haunted-house artwork mood with profile, level/EXP bar, statistics, rules, settings, Create Room, Join Friend Room, and a Store icon marked “เร็ว ๆ นี้”.
- Server-side profiles and finished-match results use Supabase Postgres with RLS. XP is awarded once per match through an idempotent security-definer RPC and retried from a local protected outbox when Supabase is temporarily unavailable.
- Level curve: Lv. 1→2 requires 100 EXP; after that the next-level requirement is 200 + 50 × (current level − 1). Excess EXP carries forward.
- Match XP: 50 completion EXP plus 20 × (number of players ranked below the player); defeat gives 50 EXP. Ties share rank and XP. A six-player win gives 150/130/110/90/70/50 XP.
- A player can join one room at a time; reconnecting the same Google account resumes the existing seat. Rooms continue to support 2–6 players.
- Real account credentials and Supabase secrets are never placed in Game log, player snapshots, or browser localStorage.

## Setup

1. Create the tables and RPC by running supabase/v1.10.0.sql once in the Supabase SQL Editor.
2. Configure Google OAuth in Supabase and Google Cloud with the deployed APP_URL and callback /auth/callback.
3. Set Railway variables from .env.example; keep ACCOUNTS_ENABLED=false until the database and callback are verified, then enable it.
4. Do not add real .env files, Supabase keys, or personal credentials to Git.

## Validation

All v1.8–v1.9 regression suites plus v110-account-test.cjs pass. Google OAuth and six-player live testing require the owner's Supabase configuration and must be verified on the playtest domain after deployment.
